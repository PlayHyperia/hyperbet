- deployment/initialization/verification signatures
- Pages and keeper post-deployment certificates, payload/file SHA-256 values, GitHub artifact IDs/digests, and immutable archive identities
- Pages build metadata and bundle scan
- service `/ready`, `/status`, source freshness, parser/index freshness, database probe, and bot recovery snapshots

- operator, security, compliance, and release approvals

Never store private keys, bearer tokens, keyed URLs, or unredacted secret-manager output in the evidence bundle.

Workflow artifact retention is only a bounded transport window. A release cannot rely on an expiring workflow artifact as its system of record: copy each exact certificate to the approved immutable archive, independently verify its canonical payload and file digest, and record the GitHub artifact identity/digest plus archive identity in the release memo before promotion. A deployment certificate proves only the endpoint checks encoded in its schema and always records `productionActivationAuthorized: false`.
